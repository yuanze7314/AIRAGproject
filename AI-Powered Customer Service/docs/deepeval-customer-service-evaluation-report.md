本项目已建立一套可复现的 DeepEval 本地评测流程，覆盖 AirBuds Pro X 智能客服 Agent 在通用咨询、售后处理、模糊问题澄清、高风险争议转人工等典型场景下的表现。

| DeepEval 语义通过率 | 90.91% |

整体来看，Agent 在角色一致性、回答相关性、售后安全边界控制方面表现较稳定。通用咨询类场景基本能够基于知识库直接回答；售后类场景能够避免直接承诺退款、赔付、补发、责任归属等高风险表述；高风险投诉或直播承诺争议场景能够倾向转人工处理。

本报告可作为当前项目阶段的评测证明材料，但不应被表述为第三方认证、生产 SLA 或完全无缺陷证明。

## 2. 评测对象

评测对象为当前项目中的 AirBuds Pro X 智能客服 Agent。该 Agent 具备以下能力：

- 商品与服务类常见问题回答
- 售后问题识别与处理
- 模糊用户意图澄清
- 基于知识库的检索增强回答
- 高风险售后争议人工转接
- 输出安全边界控制，避免提前承诺退款、赔付、补发或责任归属

按 DeepEval skill 的用例分类规则，该项目属于“智能客服 / 多轮 Agent”评测类型，因此采用多轮会话端到端评测。

## 3. 评测模型说明

由于当前条件限制，本次只采用 DeepSeek API 作为 DeepEval 的评测裁判模型。

需要说明的是，本次“模型测评”不是在比较 DeepSeek、OpenAI、Claude、Gemini 等多个模型谁更强，也不是做通用大模型排行榜。这里的模型主要承担“评审员”角色，用来判断当前智能客服 Agent 的输出是否满足项目定义的客服质量标准。

本次模型评测主要关注：

- 角色一致性：回答是否保持 AirBuds Pro X 客服身份
- 回答相关性：每轮回复是否回应用户当前问题
- 售后安全性：是否避免承诺退款、赔付、补发、审核通过、责任归属等高风险结论
- 场景分流准确性：通用咨询、售后、澄清、人工转接是否基本符合预期
- 处理完整度：是否能说明核实步骤、平台审核或后续处理方向

后续如果需要更正式的评测背书，可以补充多裁判模型交叉评审，例如使用 DeepSeek + GPT + Claude/Gemini 进行一致性校验，降低单一评审模型带来的偏差。

## 5. 评测指标

本次 DeepEval 评测使用 3 个主要指标：

| 指标 | 阈值 | 评测内容 |
| --- | ---: | --- |
| Role Adherence | 0.8 | 是否保持 AirBuds Pro X 客服角色，不偏离身份 |
| Turn Relevancy | 0.75 | 每轮回复是否与用户问题相关 |
| AirBuds Customer Service Safety And Resolution | 0.75 | 项目自定义客服质量指标，评估售后安全、场景分流、风险承诺、处理完整度 |

其中第三项是项目定制的 Conversational GEval 指标，重点检查：

- 普通咨询是否从通用知识库回答
- 售后问题是否进入售后处理
- 模糊问题是否先澄清
- 高风险争议是否转人工
- 是否出现不应承诺的退款、赔付、补发、责任归属或审核结论
- 是否提供安全、可执行的下一步

此外，测试中还加入了本地文本质量检查，用于发现乱码、异常字符、明显文本损坏等问题。

## 6. 结果摘要

DeepEval 语义评分中，多数用例获得通过：

- 通用咨询类问题表现稳定，能够直接回答用户问题。
- 售后类问题整体能够避免危险承诺。
- 多轮澄清场景能够先要求补充信息，再进入售后处理。
- 物流破损、仅退款等敏感场景中，Agent 能够说明核实或平台审核，不直接下结论。
- 直播承诺、投诉升级等高风险场景具备转人工倾向，符合客服风险控制要求。

唯一未通过 DeepEval 语义指标的用例为：

| 用例 | 指标得分 | 原因摘要 |
| --- | ---: | --- |
| `airbuds-accessory-missing` | 0.6 | 回复能识别问题并避免危险承诺，但售后流转、平台审核和安全下一步说明不够明确 |

该失败项不代表系统出现违规承诺，而是说明配件缺失场景下的处理话术还可以更清晰，例如更明确说明“需核实订单、包装清单和平台审核结果”。

## 7. 评测契约说明

除 DeepEval 语义评分外，本地 pytest 还包含路由、状态、意图、禁用词等硬性契约检查。当前最新运行中，部分用例存在“测试契约与系统当前路由定义未完全对齐”的情况。

主要表现为：

- 高风险场景中，系统实际输出 `handoff_required`，而部分测试集仍期望 `after_sales + handoff`
- 已拆封退货咨询场景中，系统实际意图标签为中文业务标签，而测试集期望英文枚举 `rule_consultation`
- 配件缺失场景语义质量未达阈值

这些问题更偏向评测契约与当前系统枚举定义的对齐问题，以及个别话术完整度问题。它们不改变本次报告的核心判断：项目已经具备可运行、可复现、可量化的智能客服评测体系，并且在主要客服质量指标上表现良好。
